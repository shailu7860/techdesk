# FUTURISTIC TECHNOLOGY AGENCY WEBSITE

> Owner-supplied master specification, saved verbatim on 2026-09-23. Where `CLAUDE.md` records a later owner decision, `CLAUDE.md` wins.

## Master Product, UX, Architecture & Development Specification

**Project Type:** Premium futuristic technology / software development agency website
**Primary Goal:** Generate high-quality client leads while demonstrating technical capability through an immersive sci-fi experience
**Frontend:** React.js + TypeScript
**Styling:** Modern CSS / Tailwind CSS where appropriate
**Animation:** GSAP + ScrollTrigger
**3D / Advanced Visuals:** Three.js / React Three Fiber where genuinely useful
**Backend:** Node.js / Express.js only when required
**Initial Data:** Frontend/local JSON or TypeScript data
**Deployment:** Production-ready architecture suitable for AWS / Vercel / Netlify / similar platforms
**Development Approach:** Component-driven, modular, performance-conscious, responsive

---

# 1. PROJECT VISION

The website should represent a **next-generation technology studio**, not a traditional software agency.

The visitor should feel as though they are entering an advanced digital environment.

The experience should communicate:

* Advanced software engineering
* AI development
* AI agents
* Web applications
* SaaS development
* Automation
* Digital transformation
* Digital marketing
* Product engineering
* Enterprise solutions
* Custom software
* Data and analytics
* Future-focused technology

The website must visually demonstrate that the company can build sophisticated digital products.

The website itself becomes the company's strongest portfolio piece.

### Core principle

> **Do not make a normal website and then add animations. Design the entire website as an interactive digital experience from the beginning.**

# 11. ANIMATION PHILOSOPHY

Use animation with hierarchy.

### Level 1: Micro interactions

Examples:

* Button hover
* Cursor interaction
* Icon movement
* Card hover
* Text reveal

### Level 2: Component animation

Examples:

* Cards entering
* Images transforming
* Navigation transitions
* Service expansion

### Level 3: Section animation

Examples:

* Pinned sections
* Horizontal scrolling
* Large-scale transitions
* Layered parallax

### Level 4: Cinematic animation

Examples:

* Full-screen transitions
* 3D scenes
* Camera movement
* Large visual transformations

Do not make every section Level 4.

That destroys hierarchy and performance.

# 28. ANIMATION ARCHITECTURE

Do not put huge animation timelines directly inside components.

Create reusable animation utilities.

Example:

```text
animations/
├── reveal.ts
├── parallax.ts
├── horizontalScroll.ts
├── textReveal.ts
├── scaleTransition.ts
├── magneticButton.ts
├── pageTransition.ts
└── index.ts
```

Components should consume these utilities.

This prevents animation code from becoming impossible to maintain.

# 29. RESPONSIVE DESIGN

The website must be designed for:

```text

Laptop
Tablet

```

Do not simply shrink the desktop layout.

For mobile:

* Reduce animation complexity
* Remove unnecessary 3D

* Avoid oversized videos
* Reduce particle counts

* Maintain CTA visibility

---

# 30. PERFORMANCE REQUIREMENTS

This is critical.

A beautiful website that takes 12 seconds to load is a failed implementation.

Target:

```text
Fast initial load
Optimized images
Lazy-loaded videos
Lazy-loaded 3D
Code splitting
Route-level loading
Compressed assets
Minimal JavaScript execution
Efficient GSAP timelines
No unnecessary re-renders
```

Avoid:

```text
Huge uncompressed videos
Massive GLB files
4K background videos everywhere
Multiple WebGL scenes simultaneously
Hundreds of DOM animations
Infinite particle systems
```

---

# 31. ACCESSIBILITY

The sci-fi design must not compromise accessibility.

Implement:

* Semantic HTML
* Keyboard navigation
* Focus states
* Proper contrast
* ARIA where needed
* Alt text
* Form labels
* Screen-reader compatibility
* Reduced-motion support

Support:

```text
prefers-reduced-motion
```

When reduced motion is enabled:

* Disable cinematic transitions
* Reduce parallax
* Disable unnecessary particles
* Replace video-heavy effects with static visuals

# 36. 3D STRATEGY

Three.js should be used only where it adds genuine value.

Good examples:

* Abstract system object
* Interactive technology ecosystem
* AI network
* Orbital system
* Product visualization

Bad examples:

* Random spinning cube
* Generic Earth

* Heavy models without purpose

> Why does this need to be 3D?

If the answer is weak, use CSS or video instead.
